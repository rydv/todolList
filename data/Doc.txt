Rule Sheet Structure Documentation
This document outlines the structure and requirements for the CSV file containing the list of rules to be processed by the application. The rule sheet must follow the specified format to ensure accurate processing and validation of rules.

CSV File Structure
The CSV file should contain the following columns:

Rule Id: Unique identifier for the rule.
Rule Type: The type of the rule (e.g., "exact", "expression", "operation").
Country: The country code associated with the rule.
Local Acc No: Local account number associated with the rule (use "ALL" for all accounts).
Amount: Amount condition (use "same" for the same amount).
Value Date: Value date condition (use "No" if not applicable).
L/S: Debit or credit indicator (e.g., "L" for debit, "S" for credit).
D/C: Debit or credit code (e.g., "A" for credit, "D" for debit).
Ref 1: Reference field 1 containing exact values and expressions.
Ref 2: Reference field 2 containing exact values and expressions.
Ref 3: Reference field 3 containing exact values and expressions.
Ref 4: Reference field 4 containing exact values and expressions.

Field Definitions
Rule Id: A unique identifier for each rule. This is a mandatory field.
Rule Type: Specifies the type of rule. Possible values are "exact", "expression", and "operation".
exact: Matches exact text values.
expression: Matches based on regular expressions.
operation: Involves operations on matched values (e.g., replacing characters).
Country: The country code for the rule. Use standard country codes (e.g., "UK" for the United Kingdom).
Local Acc No: The local account number. Use "ALL" to apply to all accounts.
Amount: Condition for the amount. Use "same" if the amount should be the same.
Value Date: Condition for the value date. Use "No" if not applicable.
L/S: Indicates whether the transaction is a debit or credit. Use "L" for debit and "S" for credit.
D/C: Indicates the debit or credit code. Use "A" for credit and "D" for debit.
Ref 1, Ref 2, Ref 3, Ref 4: Reference fields containing the exact values and expressions to match. These fields can contain exact text, regular expressions, or operations as defined below.
Reference Field Syntax
Exact Value:
Syntax: |EXACT|<value>
Example: |EXACT|Service Charge Reversal
Regular Expression:
Syntax: |EXP|<regex>
Example: |EXP|8\d{5}
Operation:
Syntax: |EXACT|<value>|EXP|<regex>|OP|<operation>-<old>-<new>
Example: |EXACT|ATM WDR AT 2164 MDS |EXP|(\d{2}:\d{2}:\d{2})|OP|REP-:-
Operations
Operations are used to manipulate the extracted values from regular expressions. Currently, the following operation is supported:

REP: Replace a character or string with another string.
Syntax: |OP|REP-<old>-<new>
Example: |OP|REP-:-
Processing Logic
The application processes each rule based on its type and the values provided in the reference fields. The exact value rules match exact text values, expression rules match based on regular expressions, and operation rules perform operations on matched values to validate the conditions.

Example Usage
Given the rule RULE004:

Ref 1: |EXACT|ATM WDR AT 2164 MDS |EXP|(\d{2}:\d{2}:\d{2})|OP|REP-:-
Ref 2: |EXP|(\d{6})
Ref 1 matches transactions with text ATM WDR AT 2164 MDS followed by a time in HH:MM:SS format.
The operation REP-:- replaces colons : in the time with an empty string.
Ref 2 then matches the transformed time format HHMMSS.
Transactions satisfying these conditions are considered valid matches for RULE004.
